The free, open base of NovaByte OS.

NovaByte Open Source Project (NBOSP) is a browser-based operating system foundation you run, fork, and build on top of. No edition system, no update pipeline, no bloat — just a minimal OS that gets out of your way.

View on GitHub Run it locally
Read this before you download. NBOSP is a foundation, not a finished product. The apps are intentionally bare bones — if you open Files, you can browse files. That's roughly the level across the board. It's the raw skeleton you fork and build on, not a competitor to a polished consumer OS.

Who it's for

Built for developers, not everyone.

NBOSP is heavily developer and engineer focused. Expect fewer features than the full product — that's not a bug, it's the point.

NBOSP is

  • A minimal, fast, stock OS with basic security built in
  • Apache 2.0 licensed — copy, modify, fork, sell, redistribute
  • Feature-frozen apps that keep getting bug and security fixes
  • A skeleton meant to be forked and built on top of
  • Actively maintained — fixes ship faster than the full product

NBOSP is not

  • A polished, consumer-ready daily driver
  • Getting new user-facing features (Settings and dev apps excepted)
  • Bundled with an update pipeline or telemetry of any kind
  • A competitor to the full closed-source NovaByte OS release
  • A finished product — read that twice before you file a feature request
What's inside

Fourteen apps. Pulled from the source, not the pitch.

These descriptions come straight from what the code actually does — including what it deliberately doesn't do.

📁 Files
Icon/list view, sort, search, copy/cut/paste, trash and restore, drag-and-drop import screened by the built-in scanner. No tabs, no split panes, no cloud sync.
📝 TextEdit
Plain text editor with line numbers, word count, Tab indentation, auto-close brackets. Single file only — no tabs, no markdown preview.
💻 Terminal
Real shell emulator — ls, cd, grep, pipes, redirects, aliases, tab autocomplete, multiple tabs. Runs against the VFS, not a real system shell.
🌐 Browser
NW.js WebView rendering, tabs, bookmarks, history, incognito, find-in-page, popup blocker. No extensions, no sync, no password manager.
📧 Email
Multi-account IMAP/POP3/Exchange, search, compose, batch-select. No filters, no tags, no offline cache.
📦 App Manager
Install .novaapp packages by drag-and-drop, run every file through the built-in scanner first, manage web apps, verified/unverified badges. No app store, no update management.
⚙️ Settings
7 themes, accent picker, username, storage, privacy, accessibility. The one app still actively developed — it controls the OS's visual identity.

Questions

Before you file an issue, check here.

Why does NBOSP need npm start to run nw . instead of a normal Node server?

NBOSP ships as an NW.js (Node-WebKit) app, not a browser-hosted page — package.json's start script is nw ., which launches the bundled Chromium-based runtime with full Node access in the window context. A prestart hook runs scripts/bootstrap.js first, which checks if node_modules is missing or stale against package-lock.json and runs the install for you.

Do I need to trust a certificate every time I launch it?

No — only once. On first launch NBOSP generates a local HTTPS certificate and CA under the hood; your OS prompts you to trust it a single time, and every launch after that is warning-free HTTPS.

What actually happens when I install a .novaapp package?

Every file inside the package is run through the built-in scanner before any trust or integrity checks happen. A flagged file blocks the install outright with no override — there's no way to force-install something the scanner rejects. Packages are also checked against the built-in trust store for a Verified/Unverified badge based on signature checks.

Is Developer Mode safe to leave on?

Not by default — no. Apps like Console (arbitrary JS in the full OS context, no sandboxing) and Modules (hot-reload with the ability to execute arbitrary module paths at runtime) skip the confirmation prompts the standard app set has. Treat Developer Mode as a debugging posture, not a daily-driver setting.

Why does the App Manager have no update system?

It's intentional, per the app's own scope: install by drag-and-drop or URL, pin/unpin, enable/disable, auto-launch on boot — no app store or catalogue, no update management. NBOSP's apps are feature-frozen by design; they get bug and security fixes, not new capability surface.

What's the difference between NBOSP and the full NovaByte OS release (v1/v2/v3)?

NBOSP (this repo, under /NBOSP) is the Apache 2.0 foundation — minimal, feature-frozen apps, no update pipeline, no telemetry, meant to be forked. The versioned v1/, v2/, v3/ releases are the full closed-source product built on top of it, distributed as a compiled executable via Releases only.

Get started

Running NBOSP takes one command.

1
Clone and start

No separate install step — a fresh clone launches with npm start.

2
Trust the local certificate, once

On first launch NBOSP generates a local HTTPS certificate and CA. Your OS will prompt you to trust it — accept once, and every launch after that is warning-free HTTPS.

3
Build on it

Clear extension points for new API endpoints, proxies, middleware, and rate limit tiers. No global state, no tight coupling between modules.
